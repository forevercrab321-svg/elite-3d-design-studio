# Shorts 第 3 版脚本（2026-10-25）

> 第 2 版（整局延时，`release/youtube-shorts/`）被用户否了：没有吸引力。下面是诊断和重做方案。标准见 `.claude/skills/grow-sales-team/SKILL.md`「短视频制片」。

## 第 2 版为什么不行

| 问题 | 表现 | 改法 |
| --- | --- | --- |
| 第 1 秒没有钩子 | 开头是普通街景 + 一行数字字幕 | 第 1 秒就让极小的机器和巨大的地标同框，配一个问题 |
| 概念说不清 | 「From 5 kg to 377 TONNES」需要先懂游戏才明白 | 一句话：「这辆小车能吃掉埃菲尔铁塔吗？」 |
| 没有高潮 | 三局都没吃完地标，结尾停在街上 | 必须拍到地标倒下（巴黎那局已经长到 621 吨，够拆塔） |
| 节奏匀速 | 全程 0.5 秒/帧，17 秒看起来都一样 | 开场实时 → 成长快进 → 攻塔 3 倍速 → 倒塌慢放 |
| 画面杂 | 名字标签、高空俯视，主角很小 | 低机位，`clip=1` 只留质量数字 |
| 不能循环 | 结尾和开头接不上 | 结尾巨大的机器 → 跳回开头的小车 |

## 脚本 1 · 小车 vs 埃菲尔铁塔（样片在做）

- **标题：** Can a tiny car eat the Eiffel Tower? 🗼
- **中文：** 这辆小车能吃掉埃菲尔铁塔吗？
- **分镜（约 20 秒）：**
  - 0–2 秒（实时，低机位）：比长椅还小的机器冲向远处的铁塔。字幕：「Can this eat THAT?」
  - 2–8 秒（快进）：在巴黎街头越吃越大，左上角质量数字一直跳。字幕：「5 kg…」→「500 kg…」→「50 t…」
  - 8–14 秒（3 倍速）：地标开放，巨大的机器冲向塔脚，一根一根吃掉。
  - 14–18 秒（实时或慢放）：最后一块被吃，铁塔倒下，出现「EIFFEL TOWER DOWN!」横幅。
  - 18–20 秒：停在空荡的广场上，接回开头的小车（循环）。
- **拍摄：** `tools/shorts/eiffel.mjs`。真实一局，质量全部来自游戏；只用脚本控制「往哪开」和镜头。

## 脚本 2 · 越大越能吃（阶梯递进）

- **标题：** I ate a trash can… then a car… then a building
- **分镜：** 每 3 秒一个台阶。画面上是「我能吃的最大东西」，同时标出名字：垃圾桶 → 摩托 → 汽车 → 卡车 → 楼房 → 地标。每一级都是机器扑上去那一下的实时镜头，台阶之间用快进衔接。
- **拍摄：** 同一局里按 tier 截取吃掉对应物件的时刻。需要「吃掉事件」时间戳，让 `eatObject` 事件写日志。

## 脚本 3 · 吃掉对手（反转）

- **标题：** He thought he was bigger 😳
- **分镜：** 两台机器对冲。看起来对手更大，我方冲刺，一口吞掉。屏幕弹出「BURP」气泡，镜头拉远露出排行榜第 1。
- **拍摄：** 真实对局中「吃掉对手」的时刻，从事件日志里找，截前后各 3 秒。

## 发布

- YouTube Shorts、TikTok、小红书同一条视频。标题按平台改写，链接带 utm（见 `promo-posts-week1.md`）。
- 每条只发一次，72 小时后看 3 秒留存和完播率，留存最好的那条的开头用到下一条。
