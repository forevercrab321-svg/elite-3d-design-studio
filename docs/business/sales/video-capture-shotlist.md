# GROW EVERYTHING · 短视频录屏清单（给工程师）

> 用途：为 `tiktok-7day-plan.md` 的 14 条视频和 `creator-outreach-plan.md` 的达人素材包提供原始镜头。
> 编写日期：2026-09-24 · 按优先级排序：**P0（6 个，必须在 D1 前录完）→ P1 → P2**。
> 本清单**不要求改代码**。录制中发现需要代码支持的地方，记在 §5「工程需求（不在本周做）」里，由用户决定是否排期。

---

## 0. 录制红线（先读）

1. **只录游戏里真实发生的事。** 不用调试手段制造正常游戏里做不到的画面（例如直接改体型、瞬移到地标旁边），也不在后期合成游戏里没有的台词或特效。
2. **加速、慢放都要在画面角落标注**（`×12`、`0.5×`），剪辑时加上。原始素材保持 1×。
3. **标「真人」的镜头必须是真人。** 真人对局由团队成员在私人房间（`?room=`）里打。含 AI 机器人的镜头，在文件名里标注 `_bots`，剪辑时字幕不能写「真人」「网友」。
4. **不录私人信息**：浏览器地址栏、书签、系统通知、聊天软件里的真实账号名，都要关掉或打码。房间号在成片里打码。
5. 挑战类镜头（S05、S10 相关）**如实保留结果**，失败的也留着，不重复录到成功后再假装是「一次成功」。

## 1. 通用录制设置

| 项目 | 设置 |
| --- | --- |
| 地址 | `https://grow-everything.vercel.app/game/`（线上版）或本地 `npm run build:web` 的产物 |
| URL 参数 | `?quality=high`（画质最高档）· `?lang=en`（TikTok 素材）/ `?lang=zh`（抖音、小红书素材）· `?seed=<N>`（固定布局，方便重录同一机位）· `?room=<房间号>`（私人房间，真人局必须用） |
| 帧率 | 60 fps |
| **横屏 1920×1080** | 浏览器全屏（F11），显示器分辨率 ≥ 1920×1080，录制输出 1920×1080。YouTube 横版、达人素材包用 |
| **竖屏 1080×1920** | 方法 A（首选，先试）：桌面 Chrome，**不开触屏模拟**，把窗口视口调成 1080×1920（DevTools 响应式模式，关闭「touch」）。游戏只在触屏设备上显示「请横屏」提示，桌面端不会，但**竖屏下 HUD 布局没有被专门测过，录之前先截一张图检查**。方法 B（备选）：横屏录 3840×2160，后期按 9:16 裁中间（1215×2160 → 缩放到 1080×1920）。4K 下帧率可能下降，先确认能稳定 60 fps |
| 编码 | OBS：H.264 CQP 18 或码率 ≥ 40 Mbps；或 ProRes 422。**游戏声音单独一条音轨**（剪辑要用喇叭、打嗝、倒塌声） |
| 文件命名 | `S<编号>_<城市>_<横|竖>_<en|zh>_<take>[_bots].mp4`，例：`S03_paris_v_en_t2.mp4` |
| 存放 | 原始素材不进 git 仓库（体积大）。放到团队共享盘，路径记在本表 §4 的「交付」栏 |

**相机说明**：游戏使用跟随相机，鼠标拖动可以旋转 / 俯仰，大约 1.2 秒不动鼠标会自动转回车尾方向。体型越大，相机越远越高。低机位镜头要在小体型时录，一边开一边用鼠标往上抬视角，把远处地标带进画面。

## 2. P0 镜头（6 个，D1 前必须完成）

### P0-1 · S05 · 一局完整连续录制：从易拉罐到地标倒塌（巴黎 + 上海）

- **用于**：V01、V02、V09、V10、V14，以及所有加速段落
- **城市**：巴黎（英文界面）、上海（中文界面）各至少 1 局；纽约为 P1
- **体型阶段**：1 级开局 → 5 级城市级，全程不间断
- **要触发的事件**：吸入易拉罐 → 汽车 → 小楼（巴黎：Café house / Haussmann block；上海：石库门）→ 地标分段拆除 → 「EIFFEL TOWER DOWN! / 拆除东方明珠！」横幅
- **视角**：默认跟随相机；每次升级后停顿 1 秒，让镜头拉远的过程完整入镜
- **格式 / 时长**：横屏 1920×1080 + 竖屏 1080×1920，各一局完整录制（≤ 300 秒 / 局，也就是游戏规定的一局时长）
- **注意**：本清单**不确定**正常对局里能否在 300 秒内把地标拆完（取决于对手和路线）。先试 3 局：
  - 能拆完：保留最流畅的一局。
  - 拆不完：如实报告给短视频岗，脚本改成「挑战失败」版本（V10 已预留）。**不要用调试手段补。**
- **对手**：可以是 AI（文件名标 `_bots`），也可以是真人

### P0-2 · S02 · 东方明珠倒塌（上海）

- **用于**：V02、V06（主推钩子 #2）、V10、V12、V13、达人素材包
- **体型阶段**：城市级（可以拆地标）
- **事件**：塔柱被扯走 → 下球体开始倾倒 → 塔身、上球体、尖顶依次倒下 → 「拆除东方明珠！」横幅 → 头顶「嗝~ 😋」
- **视角**：① 跟随相机（默认）；② 用鼠标把相机转到侧面，让整座塔的倒下过程都在画面里（广角感）。两种视角各录一次，需要两局
- **格式 / 时长**：竖屏 + 横屏；每条从拆第一根塔柱前 3 秒开始，到横幅消失后 2 秒结束（约 15–25 秒）
- **语言**：`?lang=zh` 为主，另录一条 `?lang=en` 给 V13 用

### P0-3 · S03 · 埃菲尔铁塔倒塌（巴黎）

- **用于**：V01（主推钩子 #1）、V09、V13、英文达人素材包
- **体型阶段**：城市级
- **事件**：塔腿被扯下 → 一层平台 → 二层 → 上塔 → 塔尖依次倒下 → 「EIFFEL TOWER DOWN!」横幅 → 「BURP~ 😋」
- **视角**：跟随 + 侧面广角，各录一次
- **格式 / 时长**：竖屏 + 横屏，每条 15–25 秒
- **语言**：`?lang=en`

### P0-4 · S04 · 真人互吃：被吃爆开 + 打嗝 + 喇叭（双视角）

- **用于**：V03（主推钩子 #3）、V04、V07、V09、V12、达人私信跟进片段
- **城市**：纽约为主（黄色出租车和亮色建筑，对比强）；上海补一条（V04 要用）
- **体型阶段**：2–3 级（汽车级），两台机器体型差 ≥ 1.25 倍才能吃
- **事件（按顺序）**：
  1. 大的一台追小的一台，两台都进入画面，大眼珠在晃
  2. 小的一台按喇叭（橡皮鸭）求饶，头顶出现 📯
  3. 被吃：像气球一样爆开，彩色碎片，屏幕出现「YOU GOT EATEN / 你被吞掉了」
  4. 吃人方头顶「BURP~ 😋」；随后按悲伤长号
  5. 被吃方 3 秒后重生，出现「RESPAWN · 3 s INVULNERABLE」提示
- **人员**：**必须 2 名真人**（私人房间），两台电脑**同时录**，分别得到吃人方视角和被吃方视角
- **准备**：两个测试账号要事先装备好「橡皮鸭」和「悲伤长号」喇叭（用金币在商店里正常购买；金币不够就正常多打几局。**不改本地存档，不改代码**）
- **格式 / 时长**：竖屏为主（1080×1920），每个视角录 3–5 次，每次 20–40 秒
- **语言**：en、zh 各一组

### P0-5 · S01 · 开局低机位：小机器 + 易拉罐 + 远处地标同框（巴黎 + 上海）

- **用于**：V01、V02、V10、V14 的第 1 帧（整个计划里最重要的一帧）
- **体型阶段**：1 级，刚开局，还没吃东西
- **构图**：机器正对镜头（相机绕到车头前方），车顶大眼珠清楚可见；画面里有 1–3 个易拉罐；**远处背景能看到地标**（埃菲尔铁塔 / 东方明珠）
- **做法**：用固定的 `?seed=` 反复开局，找到一个能同时看到地标的出生点，然后把 seed 和出生点记下来，方便重录。相机能不能转到车头方向、会不会自动转回，需要实测（大约 1.2 秒不动鼠标会自动转回车尾，所以录的时候要一直轻轻拖着鼠标）
- **格式 / 时长**：竖屏 1080×1920 为主，每个城市 3 条，每条 5–8 秒（包括吸进第一个易拉罐）
- **拍不出来时**：如实报告，并在 §5 提一个「拍照模式」工程需求。退路是改用「小机器 + 易拉罐」特写（不带地标）作为第 1 帧，地标放在第 2 秒出现

### P0-6 · S12 · 手机实拍：点链接 → 横屏 → 直接开玩（iOS + Android）

- **用于**：V11（转化型）、V12、所有「无需下载」的证明镜头
- **拍摄方式**：**第二台相机 / 手机拍第一台手机**（不是屏幕录制），画面里要看到手和手机
- **流程**：
  1. 聊天界面里（用团队内部测试账号，名字打码）点开游戏链接
  2. 手机在竖屏时会出现「请把手机横过来玩」提示 → 点一下进入全屏横屏（Android Chrome 会自动锁定横屏；iOS Safari 需要手动转手机）
  3. 进入大厅 → 进入私人房间 → 用虚拟摇杆移动、点冲刺、吃掉一个朋友
- **要求**：**加载时间真实保留，不剪掉**；在另一条屏幕录制里记下从点击链接到开局的真实秒数（V11 字幕的数字以这个为准）
- **设备**：iPhone（Safari）+ 一台 Android（Chrome）各一条。另外单独测一次 **TikTok App 内置浏览器**里打开链接能不能正常玩——结果直接影响 TikTok 的转化，必须报告
- **格式 / 时长**：实拍 4K 或 1080p 竖屏，每台设备 30–60 秒；同时录一条手机屏幕录制（横屏）
