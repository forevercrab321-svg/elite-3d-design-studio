# GROW EVERYTHING · 第一周裂变活动：「首周四人局挑战」

> 岗位：社群与裂变 · 编写日期：2026-09-24 · 状态：**NEEDS REVIEW**（活动上线、对外文案须用户确认）
> 配套：`docs/business/sales/community-launch.md`（社区首发把第一批玩家带进来，本活动让他们把朋友带进来）
> 依据的代码现状：`game/src/config/cosmetics.ts`、`game/src/arena/arenaMain.ts`、`game/src/arena/share.ts`、`game/src/arena/ArenaSession.ts`、`game/src/backend/telemetry.ts`

## 1. 现有系统（已核对代码，不需要新做）

| 礼物 | 解锁条件（代码） | 埋点 |
| --- | --- | --- |
| 🎉 派对帽 `party` | 在分享面板点任何一个分享渠道（`hooks.shared(channel)` → `gift('share')`）。注意：点了就算，不校验是否真的发出去 | `share_click {channel}`、`gift_unlock {rule:'share'}` |
| 💗 好友限定涂装 `buddy` | 一局结算时，房间 roster 里除自己外有 ≥1 个真人（`friends >= 1`） | `gift_unlock {rule:'friend1'}` |
| 👑 四人团皇冠 `crown` | 结算时除自己外有 ≥3 个真人（`friends >= 3`，即 4 真人同局） | `gift_unlock {rule:'friend3'}` |

- 邀请链接：`inviteInfo()` 生成干净链接，只带 `?room=XXXX`（去掉 name/lang/test）。分享渠道：系统分享、微信（桌面给二维码）、小红书、抖音、TikTok、Instagram（复制后打开 App）、WhatsApp / X / Telegram / Facebook / LINE（带参分享链接）、复制。
- 中途加入：一局 300 秒，最后 25 秒之前进房的人会**顶替最弱的 AI**（`admitLateJoiners`，`dropInCutoffSeconds: 25`），不用等下一局。
- 礼物进度存在浏览器 `localStorage`（`progress.ts`），换设备或清缓存会丢。
- 网页版没有广告、没有真钱付费（`WebPlatform.ts`：`adsAvailable = false`）；三件礼物都是 `price: 0` 的外观，**不影响数值**。

## 2. 活动设计

### 名称与一句话
- 中文：**首周四人局挑战**——「拉 3 个朋友打完一局，4 个人一起戴上皇冠」
- English: **Launch Week Squad Challenge** — "Finish one match as a squad of four and everyone gets the crown."

### 时间（真实截止，不做假倒计时）
- 与社区首发同步：D1 到 D7（示例：2026-09-29 00:00 至 2026-10-05 23:59，北京时间），日期由用户最终确定。
- **截止后皇冠照样能拿**（`friend3` 规则是永久的）。活动只是「首周」的主题包装和社区话题，不宣称「限时」「错过就没了」。文案里只写「首周挑战」，不写倒计时、不写「仅剩」。
- 如果用户想要一个真正只在首周发放的纪念物（例如「首周纪念徽章」），那是真实限量，可以做，但需要工程改动（见第 5 节可选项 E5），并且要在文案里写清楚截止时间。未经用户确认不做。

### 三步阶梯（全部用现有礼物）
1. **分享一次 → 派对帽**（门槛最低，教会玩家「分享面板在哪」）
2. **和 1 个朋友打完一局 → 好友限定涂装**（第一次体验「朋友在同一个城市里被我吃掉」）
3. **4 个真人打完一局 → 每人一顶四人团皇冠**（这是活动主奖；4 个人**同时**拿到，天然会拍照/截图）

### 首批玩家从哪来
- 社区首发帖（HN / Reddit / V2EX / B站 …）带来的玩家在首局结束后看到挑战提示 → 分享给自己的朋友。
- 社区帖本身可以加一句：「拉朋友一起玩能解锁免费的好友外观」——只陈述事实，不做「分享才能玩」之类的门槛。

## 3. 玩家为什么愿意分享？（逐条过）

| 动机 | 对应设计 | 风险 / 注意 |
| --- | --- | --- |
| **这游戏和朋友玩才最好笑**：互相吞、地标倒塌时抢最后一口 | 4 人局是游戏本来的形态，AI 只是补位；邀请的理由是「一起玩」，不是「帮我点一下」 | 如果单人体验就很差，没人会拉朋友——先看社区反馈的留存 |
| **大家一起拿到的奖励**：皇冠要 4 个人同局才有，而且 4 个人同时拿 | 奖励给「一起玩」的所有人，不是只奖邀请者，所以被邀请的朋友也有理由留到结算 | 不奖励「邀请人数」，避免刷邀请、骚扰群发 |
| **身份展示**：皇冠 / 好友涂装是买不到的（`price: 0` 且只能靠礼物规则解锁） | 在对局中其他人能看到，是「我有朋友一起玩」的社交证明 | 不能暗示付费能买（本来也买不到） |
| **分享成本低**：一键分享面板，微信桌面有二维码，手机走系统分享 | 已有 | 微信 / 小红书 / 抖音只能「复制 + 打开 App」，要粘贴一次 |

## 4. 朋友点开后 10 秒内能玩上吗？（逐步过流程）

| 步骤 | 现状（代码） | 判断 |
| --- | --- | --- |
| ① 朋友在微信/Discord 里点链接 | `?room=XXXX` 进入同一房间（`SupabaseNet.connect(code)`） | ✅ 前提：Supabase 已接通（未接通时 `backendConfigured()` 为假，朋友会进入**自己的单人局**，邀请完全无效） |
| ② 页面加载到大厅 | 3D 场景、音频、城市资源加载时间 **未实测**（本环境访问不到线上域名） | ❓ 待测：在中端安卓 + 4G 下计时。超过 10 秒就是本活动最大的漏斗损失 |
| ③ 大厅 → 进入对局 | 新玩家默认 `joined = true`；如果房主正在一局里，最后 25 秒前进来会**直接顶替 AI**，不用等 | ✅ 一局中途：点开即进 |
| ④ 房主还在大厅 | 需要房主按开始（有 ready 流程） | ⚠️ 朋友要等房主操作；可接受，但需要大厅里明显显示「等 XX 开始」 |
| ⑤ 微信内置浏览器 | WebGL / 横屏 / 全屏在微信内置浏览器里的表现 **未实测** | ❓ 待测：中国区好友的主入口就是微信 |
| ⑥ 手机横屏 | 有虚拟摇杆、横屏锁定 | ✅（已在 launch-checklist 标为完成；社区首发时再收集真机反馈） |

结论：**在 Supabase 接通、首屏加载达标的前提下，「中途加入顶替 AI」让朋友可以做到点开即玩**；两个未知项（加载时间、微信内置浏览器）必须在 D0 内测时实测，没过就先修再上线活动。

## 5. 最小游戏改动清单（给工程师；本岗位不改代码）

按优先级。P0 不做就无法衡量或活动无效；P1 显著提升转化；P2 可选。

| # | 优先级 | 改动 | 位置（参考） | 为什么 |
| --- | --- | --- | --- | --- |
| E0 | P0 | 确认线上已配置 Supabase（`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`），并用两台设备跑通「邀请 → 同房 → 结算 → 皇冠」 | Vercel 环境变量；`launch-checklist.md` 第 1 项 | 不接通则无联机、无埋点，活动不存在 |
| E1 | P0 | 邀请链接加来源标记：`?room=XXXX&utm_source=invite&utm_medium=<channel>&utm_campaign=squad_week1`。`inviteInfo()` 当前会把链接洗成只剩 `room`，需要在清洗后追加这 3 个参数（仍然不带 name/lang/test） | `game/src/arena/arenaMain.ts` `inviteInfo()`；`share.ts` 的渠道 id 作为 `utm_medium` | 现在被邀请来的新玩家在 `sessions.utm` 里是空的，**无法统计「邀请带来的新玩家」**这个本岗位的核心 KPI |
| E2 | P0 | 新埋点 `invite_open {room, first_visit}`：页面通过邀请链接打开时（`portal.invitedRoom() ?? params.get('room')` 非空）发送一次 | `arenaMain.ts` 连接房间处 | 区分「点了邀请链接的人」和「自己开房的人」，算邀请落地率 |
| E3 | P1 | `match_end` 增加字段 `friends`（本局除自己外的真人数，已有变量）和 `invited`（本会话是否从邀请链接进入） | `arenaMain.ts` 结算处 | 计算「好友局完成率」，不用再从 roster 反推 |
| E4 | P1 | 结算卡片：若 `friends` 为 1–2，显示一行提示「再拉 N 位朋友凑满 4 人，大家都能拿皇冠 👑」+ 分享按钮；已拿到皇冠则不显示 | `ArenaUi` 结算卡片 / `GIFT_HINT` 文案（`cosmetics.ts`） | 在情绪最高的时刻提示下一步；只陈述规则，不做倒计时 |
| E5 | P2（需用户批准） | 大厅显示一条活动横幅：「首周四人局挑战 · 截止 10 月 5 日」，日期写死为真实截止日，过期自动隐藏 | 大厅 UI | 真实截止时间，不是滚动倒计时 |
| E6 | P2（需用户批准） | 如要真实限量纪念物：新增礼物规则 `launch_week`（活动期内完成 `friend3` 才发放），发放时间以服务器时间为准 | `cosmetics.ts` `GiftRule`、`progress.ts` | 只有做了才能在文案里说「首周限定」 |
| E7 | 待确认 | 核实：中途加入顶替 AI 的朋友是否计入结算时的 `friends`（代码按 `session.match.roster` 里 `kind === 'player'` 计数，注释写的是「从开局就在房间的人」，两者可能不一致） | `arenaMain.ts` 第 ~259 行、`ArenaSession.admitLateJoiners` | 若中途加入者不算，朋友中途进来打完一局却拿不到礼物，会被当成 bug |

不需要改的：不加「邀请 N 人得奖励」、不加邀请排行榜、不加任何付费入口。

## 6. 衡量指标（全部来自现有或 E1–E3 新增埋点，按 `player_id` 去重）

| 指标 | 定义 | 数据来源 | 现在能算吗 |
| --- | --- | --- | --- |
| 分享率 | 有 `share_click` 的会话 ÷ 有 `lobby_view` 的会话 | 现有 | ✅（需 Supabase） |
| 分享渠道分布 | `share_click.channel` 计数 | 现有 | ✅ |
| 礼物解锁漏斗 | `gift_unlock` 按 `rule` = share → friend1 → friend3 的玩家数 | 现有 | ✅ |
| 邀请落地数 | `invite_open` 的新 `player_id` 数；或 `sessions.utm->>'utm_source' = 'invite'` | E1 / E2 | ❌ 需要改动 |
| 邀请转化率 | 邀请落地后完成 `match_end` 的比例 | E1 + 现有 `match_end` | ❌ 需要 E1 |
| 好友局完成率 | `match_end` 中 `friends >= 1` 的比例；`friends >= 3` 的比例 | E3（或暂用 `gift_unlock` 的 friend1/friend3 近似） | ⚠️ 近似可算 |
| 裂变系数 K（第一周） | 邀请带来的新玩家数 ÷ 有 `share_click` 的玩家数 | E1 | ❌ 需要 E1 |

- **目标值：未知**。没有历史数据和可引用的同类基准，不设拍脑袋目标；第一周的作用是拿到基线，第二周再定目标。
